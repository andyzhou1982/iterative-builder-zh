# 继续项目构建命令

恢复中断的循序渐进项目构建会话，从上次停止的地方继续。

## 执行步骤

### 第一步：定位项目目录

1. 如果用户提供了目录参数，使用该目录
2. 如果没有参数，使用当前工作目录
3. 验证目录中是否存在规划文件：
   - `task_plan.md` - 必须存在
   - `findings.md` - 必须存在
   - `progress.md` - 必须存在

如果规划文件不存在，提示用户：
> 未找到项目规划文件。请确保在正确的项目目录中运行此命令，或指定包含 task_plan.md、findings.md、progress.md 的项目目录路径。

### 第二步：读取规划文件

**按顺序读取以下文件**：

1. **task_plan.md** - 了解：
   - 项目目标和当前阶段
   - 技术栈决策
   - 阶段概览和完成状态
   - 关键问题和已做决策
   - 遇到的错误记录

2. **findings.md** - 了解：
   - 需求摘要
   - 技术栈详情
   - 研究发现和关键模式
   - 技术决策记录

3. **progress.md** - 了解：
   - 会话历史记录
   - 每日进度状态
   - 测试结果
   - 错误日志
   - 5 问重启检查答案
   - 下一步行动

### 第三步：执行 5 问重启检查

读取文件后，向用户确认当前状态：

```
## 项目恢复摘要

**项目名称**: [从 task_plan.md 提取]

**当前阶段**: [从 task_plan.md 的"当前阶段"提取]

**技术栈**: [从 task_plan.md 提取已确认的技术栈]

**已完成阶段**: [列出状态为 complete 的天数]

**当前进行中**: [列出状态为 in_progress 的天数]

**待完成阶段**: [列出状态为 pending 的天数]

**上次停止点**: [从 progress.md 的下一步行动提取]

---

**请确认以上信息是否正确，或者告诉我有什么需要调整的地方。**
```

### 第四步：继续构建

用户确认后：

1. **自动加载 skill** - 激活 `iterative-project-builder-zh` skill

2. **根据当前状态决定下一步**：
   - 如果有 in_progress 的阶段 → 继续该阶段
   - 如果所有阶段 complete → 询问用户是否开始下一阶段
   - 如果遇到错误 → 优先解决错误

3. **更新 progress.md** - 记录恢复会话：
   ```markdown
   ## 会话: [当前日期]

   ### 恢复会话
   - **状态:** in_progress
   - **开始:** [日期]
   - 执行操作:
     - 读取规划文件恢复上下文
     - 确认当前阶段: [阶段名]
     - 继续实现
   ```

## 注意事项

- 如果项目已完成所有阶段，询问用户是否需要：
  - 添加新功能
  - 优化现有代码
  - 生成最终文档
- 如果发现规划文件损坏或不一致，尝试修复并告知用户
- 始终在继续前确认当前状态，避免重复工作或遗漏
